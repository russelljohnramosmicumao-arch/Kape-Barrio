Kape' Bar-Rio Ordering — Server-Side Done Fix v2

ROOT CAUSE
The old Done workflow depended on:
1. browser removes the order locally
2. browser writes the receipt into local History
3. sync detects that local receipt
4. browser sends receipt + completed status to Supabase

If step 2/3 was missed, the server stayed OPEN with no receipt and the order came back.

NEW BEHAVIOR
- When the last active item is served, Ordering calls kbr_complete_paid_order directly.
- Supabase validates that the order is paid.
- Supabase validates that all active units are served.
- Supabase builds and stores the receipt itself.
- Supabase marks the order completed.
- Normal inventory completion trigger still runs.
- Revision conflicts refresh and retry using the latest server revision.

BACKEND
kbr_complete_paid_order() is already live in Supabase.

1. Open Ordering while online.
2. Press Update if shown.
3. Fully close the Ordering PWA.
4. Reopen it.
